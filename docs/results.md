## 3. 학습 시간 — 해상도를 낮춰 해결했다 (S6)

어제 `tools/bench.py` 로 병목이 **GPU** 임을 확인했다(에폭당 GPU 85초 vs 데이터
로딩 20초). 데이터 로딩을 아무리 최적화해도 소용없고, GPU 연산량 자체를 줄여야
한다는 뜻이었다. 원본이 28px 인데 224px 로 늘려 넣고 있었으므로 112px 로 낮췄다.

| 입력 | test macro F1 | 학습 시간 | 최저 클래스 F1 |
| ---: | ---: | ---: | ---: |
| 224px | 0.978057 | 33.4분 | 0.9494 (monocyte) |
| 112px | 0.974868 | **11.9분** | 0.9405 (IG) |
| 차이 | **−0.003189** | **2.8배 빠름** | |

**성능을 조금 잃었고, 그 "조금"이 얼마인지 잴 수 있게 됐다.** 아래 S3 측정으로
시드에 의한 흔들림이 0.000155 임을 알았으므로, 0.003189 는 **그 20배**다.
우연이 아니라 해상도를 낮춘 실제 대가다.

**그래도 112px 를 작업 기준으로 삼는다.** S1·S2 를 모두 통과하고, 실험 한 번이
33분에서 12분으로 줄어든다. 남은 기간에 실험을 여러 번 돌릴 수 있는 쪽이,
macro F1 0.003 보다 프로젝트에 이롭다. 최종 보고에는 두 숫자를 모두 싣는다.

## 4. 재현성 (S3)

같은 명령을 두 번 실행했다 (`res112_resnet18`, `res112_rerun_seed42`).

```
1회차 macro F1  0.974868057672553
2회차 macro F1  0.974868057672553
차이            0.0000000000
혼동행렬 동일?  True
학습곡선 동일?  True      ← 20 에폭의 손실·지표가 전부 일치
```

기준(< 0.01)을 통과한 정도가 아니라 **완전히 같다.** `src/seeding.py` 가
`cudnn.deterministic` 까지 고정하기 때문이다.

### 그러나 "같은 시드"의 범위는 좁다

| 무엇을 바꿨나 | macro F1 차이 |
| --- | ---: |
| 아무것도 (같은 명령 두 번) | **0.0000000** |
| 시드 42 → 43 | 0.000155 |
| **`--num-workers` 2 → 4** (시드는 그대로 42) | **0.0083** |
| 입력 224px → 112px | 0.003189 |

`--num-workers` 를 바꾼 것만으로 시드가 같은데도 0.0083 이 어긋난다. 워커 수가
바뀌면 증강에 쓰이는 난수 흐름 자체가 달라지기 때문이다(`docs/experiments.md`).

**시드 고정은 "명령줄이 한 글자도 다르지 않을 때"만 재현을 보장한다.** 그리고
그 흔들림(0.0083)이 해상도를 절반으로 줄인 대가(0.0032)보다 크다는 점이 중요하다.
실험을 비교할 때 인자를 두 개 이상 바꾸면 무엇이 효과였는지 알 수 없다.

## 5. 오류 분석 — 가설을 검증했고, 절반만 살아남았다 (S5)

어제 세운 가설: 남은 오분류가 **neutrophil · immature granulocytes · monocyte**
세 클래스(이하 삼각지대) 안에만 갇혀 있는 이유는 모델의 결함이 아니라 **라벨이
연속선상에 있어 모호하기 때문**이다.

가설을 그냥 두면 이야기일 뿐이므로, **틀렸다면 어떤 숫자가 나와야 하는지**를
먼저 정하고 `analyze.py` 로 쟀다.

| | 예측 | 결과 (3개 모델) |
| --- | --- | --- |
| P1 | 삼각지대 오류에서 덜 확신한다 | **판정보류** |
| P2 | 정답이 2순위에 남는다 | **판정보류** (3개 중 1개만 맞음) |
| P3 | 마진(p_예측 − p_정답)이 작다 | **판정보류** |
| P4 | 2순위에 실린 확률이 크다 | **맞음** (3개 모두) |

### P1~P3 이 판정보류인 이유 — 표본이 없다

오분류가 test 3,421장 중 **70~83장**뿐이고, 그중 삼각지대는 40~50장이다.

```
삼각지대 0.818 vs 그 밖 0.768 · 차이 +0.050 (95% 구간 −0.035 ~ +0.136)
```

95% 구간이 0 을 걸친다. **"차이가 없다"가 아니라 "이 표본으로는 말할 수 없다"**
이다. 모델이 잘 맞힐수록 오류 분석의 표본이 줄어드는, 피할 수 없는 긴장이다.

> **판정 코드를 두 번 갈아엎었다.** 처음에는 두 평균을 부등호로만 비교했는데,
> 같은 데이터로 학습한 두 모델이 **정반대 판정(3개 중 1개 / 3개 모두)** 을
> 냈다. 40장짜리 평균은 그 정도로 흔들린다. 부트스트랩 신뢰구간으로 바꾸자
> 세 모델이 일관되게 "판정보류"로 모였다. **판정이 표본에 따라 뒤집히면 그건
> 결과가 아니라 도구의 결함이다.**

### P4 — 표본을 100배로 늘려 얻은 유일한 신호

오분류 40장 대신 **맞힌 3,300장**을 봤다. 라벨이 연속선상에 있다면 그 이웃
관계는 틀린 장에서만 나타날 리 없고, 맞힌 장의 2순위에도 드러나야 한다.

| 모델 | 삼각지대 | 그 밖 | 차이 (95% 구간) |
| --- | ---: | ---: | --- |
| ResNet18 224px seed 42 | 0.0163 | 0.0056 | **+0.011** (+0.007 ~ +0.014) |
| ResNet18 112px seed 42 | 0.0156 | 0.0059 | **+0.010** (+0.007 ~ +0.013) |
| ResNet18 112px seed 43 | 0.0172 | 0.0056 | **+0.012** (+0.008 ~ +0.015) |
| **ResNet50 112px seed 42** | 0.0156 | 0.0064 | **+0.009** (+0.006 ~ +0.013) |

**네 모델에서 거의 같은 값으로 재현된다.** 구조를 바꿔도 마찬가지다. 삼각지대
클래스는 2순위에 약 3배의 확률을 싣는다 — 이웃 클래스가 실질적으로 경쟁하고
있다는 뜻이다.

> **여기서도 기준을 한 번 갈아엎었다.** 처음에는 "2순위가 이웃 클래스인가"를
> 우연(1/7 = 14.3%)과 비교했고 **여덟 클래스가 전부 통과했다.** platelet 은
> 2순위가 96.6% 확률로 erythroblast 인데 실제로는 **한 장도 안 틀린다** —
> 2순위에 실린 확률이 0.0019 에 불과한 잔여물이기 때문이다. 어느 클래스가
> 2순위인지는 모든 클래스에서 쏠려 나오므로 구분에 쓸 수 없다.
> **항상 통과하는 검사는 검사가 아니다.**

### P4 를 클래스별로 뜯어보면 — 삼각지대라는 이름이 헐겁다

| 클래스 | 2순위 | 2순위 확률 (224px) | (112px) |
| --- | --- | ---: | ---: |
| △ immature granulocytes | neutrophil | 0.0243 | 0.0245 |
| △ monocyte | immature granulocytes | 0.0243 | 0.0191 |
| basophil | immature granulocytes | **0.0145** | **0.0284** |
| erythroblast | platelet | 0.0115 | 0.0031 |
| lymphocyte | — | 0.0061 | 0.0090 |
| △ **neutrophil** | immature granulocytes | **0.0062** | **0.0067** |
| eosinophil | — | 0.0018 | 0.0019 |
| platelet | erythroblast | 0.0019 | 0.0002 |

**두 가지가 가설과 어긋난다.**

1. **neutrophil 은 낮다** (0.0062). 삼각지대의 한 축인데도 삼각지대 밖 클래스와
   비슷하다. 666장으로 가장 많고 형태가 뚜렷해서, 모델이 이 클래스만큼은
   자신 있게 분리한다.
2. **basophil 은 높다** (0.0145 / 0.0284). 삼각지대 밖인데 IG 를 2순위로 두고
   상당한 확률을 싣는다.

따라서 P4 가 실제로 말하는 것은 "세 클래스가 서로 경쟁한다"가 아니라
**"immature granulocytes 가 여러 클래스와 경쟁한다"** 에 가깝다. IG 는
monocyte·basophil·neutrophil 모두의 2순위로 등장한다.

이는 미성숙 과립구가 **성숙 단계의 중간 지점**이라는 설명과 맞아떨어진다.
연속선의 한쪽 끝(neutrophil)은 뚜렷하고, 중간(IG)이 여러 방향으로 번진다.

### 정리 — 가설은 좁혀졌다

- **살아남은 것** — IG 를 중심으로 클래스들이 실질적으로 경쟁한다는 것은
  세 모델에서 재현되는 사실이다.
- **살아남지 못한 것** — "세 클래스가 대칭적인 삼각형을 이룬다"는 그림은 틀렸다.
  neutrophil 은 그 축에 끼지 않는다.
- **아직 못 밝힌 것** — 이 경쟁이 **라벨의 모호성** 때문인지 **모델의 한계**
  때문인지는 확률 분포만으로 가릴 수 없다. 40장짜리 표본으로 P1~P3 을 재려던
  시도가 실패한 것이 그 증거다.

### 그리고 눈보다 강한 증거가 나왔다 — 다섯 모델이 같은 장을 틀린다

사람이 이미지를 보고 "라벨이 이상한데" 하고 느끼는 것은 인상이지 증거가 아니다.
같은 질문을 숫자로 물을 수 있는 형태로 바꿨다 (`tools/consensus_errors.py`).

> **서로 다르게 학습한 모델들이 같은 이미지를, 같은 방향으로, 확신에 차서
> 틀리는가?**

모델마다 다른 장을 틀린다면 원인은 학습의 우연(초기화·증강 순서)이고, 모델을
더 잘 만들면 줄어든다. 같은 장을 틀린다면 원인은 **그 이미지에** 있다.

| 모델 | 구조 | 입력 | 시드 | 오분류 |
| --- | --- | ---: | ---: | ---: |
| `effb0_112` | **EfficientNet-B0** | 112px | 42 | 68장 |
| `resnet50_112` | **ResNet50** | 112px | 42 | 86장 |
| `res112_resnet18` | ResNet18 | 112px | 42 | 83장 |
| `res112_seed43` | ResNet18 | 112px | **43** | 80장 |
| `baseline_resnet18_28px` | ResNet18 | **224px** | 42 | 70장 |

```
다섯 모델이 모두 틀린 장          26장
우연이라면 기대값                 0.00장   ← 1,310,123배
그중 같은 클래스로 틀린 장        25장  (26장 중)
그중 다섯 다 90% 이상 확신한 장   13장
```

기대값은 각 모델의 오류율(약 2%)이 독립이라고 봤을 때의 곱이다. 3,421장에서
다섯 번 겹칠 일은 사실상 없어야 하는데 26장이 겹친다.

> **재현하면 27장이 나온다.** `tools/run_all.ps1` 은 ResNet50 을 빼고 네 모델만
> 학습한다 — 혼자 120.8분이 걸려 S6(30분 이내)을 못 넘기기 때문이다. 다섯 번째로
> ResNet50 을 넣어야 26장이 된다. 바로 아래 표의 "+ ResNet50 → 26장"이 그 한 장이다.
>
> ```bash
> python train.py --arch resnet50 --input-size 112 --epochs 20 --name resnet50_112
> python tools/consensus_errors.py --runs resnet50_112 effb0_112 res112_resnet18 res112_seed43 baseline_resnet18_28px --save runs/consensus_errors.json
> ```

**모델을 더해도 줄지 않는다.** 이 숫자의 변화가 발견의 핵심이다.

| 넣은 모델 | 공통 오분류 |
| --- | ---: |
| ResNet18 3개 (시드·해상도만 다름) | 40장 |
| + EfficientNet-B0 | 27장 |
| **+ ResNet50** | **26장** |

세 번째 구조를 넣었는데 **27 → 26**, 한 장 줄었다. 겹침이 점점 좁아져 사라지는
것이 아니라 **단단한 핵에서 멈춘다.** 모델을 더 넣어도 이 26장은 계속 남을
것으로 보인다.

> **이 예측은 절반만 맞았다.** 모델을 더 넣는 것으로는 그랬지만, 원본 해상도를
> 올리자 26장이 14장으로 줄었다. 아래 「원본 해상도를 올렸다」를 보라.

**구조는 원인이 아니다.** 설계가 서로 전혀 다른 두 모델끼리도 기대값의 24배로
겹친다.

| 겹치는 두 모델 | 실제 | 우연이라면 |
| --- | ---: | ---: |
| ResNet50 ∩ EfficientNet-B0 | 41장 | 1.7 |
| ResNet50 ∩ ResNet18 (112px) | 49장 | 2.1 |
| EfficientNet-B0 ∩ ResNet18 (112px) | 39장 | 1.6 |
| EfficientNet-B0 ∩ ResNet18 (224px) | 36장 | 1.4 |

**시드도, 해상도도, 구조도 원인이 아니다.** 남은 공통점은 ImageNet 사전학습과
같은 학습 데이터인데, 후자는 배제할 대상이 아니라 **바로 그것이 결론**이다 —
학습 데이터에서 배운 기준과 이 이미지들의 라벨이 어긋난다.

> **성능이 가장 나쁜 모델을 넣어도 결과가 같다.** ResNet50 은 셋 중 macro F1 이
> 가장 낮고(0.9738) 오분류도 가장 많다(86장). 그런데도 그 86장 안에 다른 모델들이
> 틀린 26장이 그대로 들어 있다. **"덜 좋은 모델이라 더 틀린 것"으로는 설명되지
> 않는다** — 26장은 모델의 좋고 나쁨과 무관하게 남는다.

### 눈으로 본 결과 — 분엽 여부가 갈린다

`inspect_errors.py` 로 공통 오분류를 정답·예측 클래스의 대표와 나란히 놓고 봤다
(`runs/effb0_112/errors/`). 가장 많은 쌍인 `neutrophil → immature granulocytes`
8장에서 눈에 띄는 것은 **핵의 분엽 여부**다.

- **호중구 대표** — 핵이 여러 조각으로 나뉘어 있다 (분엽)
- **미성숙 과립구 대표** — 핵이 통으로 둥글거나 띠 모양이다 (미분엽)
- **틀린 이미지 8장** — 전부 미분엽이다

성숙한 호중구는 핵이 분엽되고, 미성숙 단계에서는 분엽되지 않는다. 즉 이
이미지들은 **"neutrophil" 이라는 라벨이 붙어 있지만 미성숙 단계의 모습**을
하고 있다. 모델이 확률 1.00 으로 immature granulocytes 를 고른 이유가
설명된다.

> **의학적 판정은 아니다.** 저해상도 28px 이미지이고, 필자는 혈액학 전문가가
> 아니다. 여기서 말할 수 있는 것은 "모델이 왜 그렇게 판단했는지 사람 눈으로도
> 따라갈 수 있다"까지다. 실제 라벨 오류인지는 전문가 검토가 필요하다.

### 그리고 원본 해상도를 올렸다 — 26장 중 14장만 남았다

위 다섯 모델은 시드도 구조도 입력 크기도 달랐지만, **원본 픽셀은 다섯 다 같은
28px 파일**이었다. 그래서 반론이 하나 남아 있었다.

> 28px 로 뭉개면서 사라진 단서가 있다면, 그 26장은 라벨의 문제가 아니라
> **해상도의 문제**다.

BloodMNIST 의 224px 원본(1.5GB)을 받아 같은 ResNet18 을 다시 학습하고
(`hires224_res18_112`) 여섯 번째 모델로 넣었다. 바꾼 것은 원본 해상도 하나뿐이다 —
입력 크기(112px)도 구조도 시드도 그대로다.

**먼저 인덱스부터 맞췄다.** "그 26장"은 테스트셋 번호로 저장돼 있으므로, 224px 의
3421번이 28px 의 3421번과 같은 사진이 아니면 비교가 통째로 무의미해진다.
`tools/check_alignment.py` 로 쟀다. 라벨 배열이 세 분할 모두 정확히 일치하고,
224px 를 28px 로 줄이면 픽셀 차이가 평균 **6.5** 인데 **일부러 한 칸 어긋나게
짝지으면 35.7** 이다. 5~6배로 갈리므로 인덱스를 이어 써도 된다.

> 대조군(어긋나게 짝짓기)이 없으면 앞의 6.5 는 증거가 못 된다. "혈액 도말
> 사진끼리는 원래 다 비슷하다"는 설명이 그대로 남기 때문이다.

결과는 이렇다.

```
다섯 모델이 모두 틀린 장          26장
+ 고해상도 모델도 틀린 장         14장   ← 54% 가 살아남았다
  고해상도 모델이 새로 맞힌 장    12장
```

**ResNet50 을 빼고 네 모델로 해도 같다.** `tools/run_all.ps1 -Hires` 가 내는 값은
**27장 중 15장 생존(56%)** 으로, 위의 26장 중 14장(54%)과 사실상 같은 이야기다.
어느 쪽 모델 묶음을 쓰든 결론이 바뀌지 않는다.

**통째로 남지도, 통째로 사라지지도 않았다.** 그리고 갈린 선이 우연이 아니다.

| 헷갈린 축 | 살아남은 14장 | 고해상도가 맞힌 12장 |
| --- | ---: | ---: |
| 호중구 ↔ IG (**핵의 분엽 여부**) | **11장** | 1장 |
| IG ↔ 단핵구·호염기구·림프구 (**과립·세포질 질감**) | 0장 | **10장** |
| 그 밖 | 3장 | 1장 |

**이 갈림은 바로 위에서 눈으로 본 것과 맞아떨어진다.**

- 핵이 분엽됐는지는 **28px 에서도 보이는 큰 구조**다. 해상도를 8배 올려도 새로
  얻을 정보가 없고, 그래서 11장이 그대로 남았다.
- IG 를 단핵구·호염기구와 가르는 단서는 **과립과 세포질의 질감**이다. 28px 에서는
  물리적으로 뭉개져 사라진다. 고해상도가 이 축에서만 10장을 되찾은 것이 그
  설명과 맞는다.

**확신도 함께 내려갔다.** 26장일 때는 13장을 모든 모델이 90% 이상 확신했는데,
14장에서는 5장이다. 고해상도 모델은 남은 장들에서 **망설인다.** 확신에 차서
틀리던 자리가 애매해졌다는 뜻이고, 그 이미지가 실제로 경계에 있다는 쪽의 증거다.

**어제의 예측은 절반 틀렸다.** 바로 위에 "모델을 더 넣어도 이 26장은 계속 남을
것으로 보인다"고 적었다. *모델을* 더 넣는 것에 대해서는 맞았지만, **데이터를
바꾸는 것은 다른 축**이었다. 12장은 구조를 아무리 바꿔도 못 맞혔을 장인데 원본
해상도를 올리니 풀렸다. 재현: `tools/survivors.py`, 저장본
`runs/hires_survivors.json` (살아남은 14장과 맞힌 12장의 번호가 그대로 들어 있다).

### 결론 — 상한은 있다. 다만 어제 그은 자리보다 아래다

남은 오분류를 하나로 묶어 "데이터의 성질"이라고 불렀는데, 고해상도 실험이 그
덩어리를 둘로 갈랐다.

- **12장은 해상도의 한계였다.** 모델 탓도 라벨 탓도 아니고, 28px 에 애초에 그
  정보가 없었다. 원본을 키우니 풀렸다. 이 몫은 **고칠 수 있는 것**이었다.
- **14장은 해상도로 설명되지 않는다.** 원본을 8배로 키워 준 여섯 번째 모델까지
  틀린다. 대부분(11장) 호중구 ↔ 미성숙 과립구, 즉 **성숙 단계의 경계**다.
  라벨과 형태가 어긋난다는 가설이 여기서 살아남았다.
- 따라서 **이 14장을 맞히는 쪽으로 macro F1 을 올리는 것**은 모델을 개선하는
  일이 아니라 데이터의 라벨링 관습을 외우는 일에 가깝다.

이것이 "정확도를 더 올리지 말자"는 판단(`docs/PLAN.md` 부록 E)의 근거다. 다만
근거의 크기는 26장이 아니라 **14장**으로 줄었고, 그렇게 적는 편이 정직하다.

**방법에 관해 남는 교훈이 하나 있다.** 모델을 다섯 개 만들어 겹침을 봐도
"데이터가 문제다"까지밖에 말하지 못했다. 그 안에서 *해상도의 몫*과 *라벨의 몫*을
가른 것은 모델을 하나 더 만든 것이 아니라 **데이터를 바꿔 본 것**이다. 모델을
아무리 더해도 갈리지 않는 축이 있다.

### Grad-CAM 관찰 (224px 모델)

최종 모델은 **틀린 경우에도 거의 전부 세포(주로 핵)에 히트맵이 집중**된다.
에폭 3 짜리 모델에서는 히트맵이 배경과 이미지 가장자리로 번져 있었다. 학습이
진행되면서 모델이 "어디를 봐야 하는지"를 먼저 배웠고, 남은 오류는 보는 위치의
문제가 아니게 됐다. 남은 오분류가 엉뚱한 단서 때문이 아니라는 근거다.

## 7. 한계

- **해상도는 일부만 걷어 냈다.** 224px 원본으로 다시 학습해 공통 오분류의 12장이
  저해상도 탓이었음을 보였지만(5절), 확인한 것은 **ResNet18 한 번**이다. 다른
  구조도 같은 12장을 되찾는지는 재지 않았다. 6절 이후의 성능 수치와 Grad-CAM 은
  아직 전부 28px 원본 모델의 것이다.
- **224px 도 원본이 아니다.** MedMNIST 가 이미 잘라 리사이즈한 판이다. 현미경
  원본은 더 크고, 거기서는 또 다른 단서가 살아 있을 수 있다.
- **P1~P3 을 측정하지 못했다.** 오분류가 70~83장뿐이라 표본이 부족하다.
  이 데이터셋에서 더 큰 표본을 얻으려면 일부러 나쁜 모델을 쓰는 수밖에 없는데,
  그건 다른 모델의 오류를 재는 것이라 답이 되지 않는다.
- **모호성인지 모델 한계인지 아직 못 가렸다.** 확률 분포로는 여기까지가 끝이다.
- **단일 데이터셋.** 다른 병원·장비·염색 조건은 보장할 수 없다.
- **임상 사용 불가.** 임상 검증을 거치지 않았고, 그럴 목적으로 만들지 않았다.
